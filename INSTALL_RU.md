# Установка и запуск NetScope

## Готовая Windows-программа

1. Распакуйте `NetScope-v1.0.0-Windows-x64.zip` в постоянную папку.
2. Запустите `NetScope\NetScope.exe`. Не переносите EXE отдельно от `_internal`.
3. Выберите активный Wi-Fi/Ethernet, интервал и уведомления. Разрешайте обнаружение только в своей или разрешённой локальной сети.
4. Для русского интерфейса: Settings → Language → Русский. Қазақша доступен там же.

Программа не подписана цифровым сертификатом. Архив предназначен для вашего локального тестирования. Права администратора по умолчанию не требуются.

DEMO: из терминала в папке приложения ` .\NetScope.exe --demo`. Данные DEMO сохраняются отдельно. Для настоящей сети запускайте без `--demo`.

## Исходники в VS Code

Установите Python 3.12 x64 с python.org и расширение Python от Microsoft в VS Code. Откройте **папку NetScope**, где лежит `main.py`, а не внешний архивный каталог.

В терминале PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Активировать окружение необязательно — команды явно используют его интерпретатор и не требуют изменения политики PowerShell. Если `py` отсутствует, замените первую команду полным путём к установленному `python.exe`.

В VS Code: Ctrl+Shift+P → Python: Select Interpreter → `.venv\Scripts\python.exe`. В Run and Debug выберите `NetScope (live)` или `NetScope (DEMO)` и нажмите F5.

```powershell
.\.venv\Scripts\python.exe main.py --demo
.\.venv\Scripts\python.exe -m pytest -q
```

## Где данные

`%LOCALAPPDATA%\NetScope\live` — реальные данные; `demo` — синтетические. `netscope.db` — база, `netscope.log` — локальный журнал ошибок. Для резервной копии завершите приложение через трей и скопируйте всю папку режима. Не копируйте только DB во время активной записи: SQLite использует WAL.

Интервал — 15–3600 секунд. Хранение временных рядов — 1–365 дней; очистка на запуске и после сканирования. Заметки, инвентарь и настройки остаются. Снимков сохраняется не более 100.

## Если устройств мало или нет

- Проверьте, что выбран физический Wi-Fi/Ethernet с нужной подсетью, а не WSL/Hyper-V/VPN.
- Убедитесь, что включено локальное обнаружение. Для больших подсетей `/23`, `/20`, `/16` автоматический обход запрещён; приложение объяснит ограничение.
- ICMP может блокироваться на соседних устройствах или политикой среды. Запись ARP сама по себе не считается доказательством присутствия.
- MAC, hostname, DNS, IPv6 и процесс могут отсутствовать. Пустое поле не означает ошибку программы.
- В Diagnostics DNS-проверка пропускается, если DNS отсутствует или не частный; запросы к внешним серверам не выполняются.
- Port check доступен только в карточке устройства, для разрешённой подсети и ограниченного набора портов.

При закрытии окно может уйти в трей. Для полного завершения: правый щелчок на иконке → Выход. Автозапуск включается только вручную в настройках и записывает значение HKCU Run без повышения прав.

## Демо-записи из настроек

Нажмите **Настройки → Демо-записи**. Программа покажет явно помеченный DEMO с заполненными вкладками: устройства, история и графики, трафик, соединения, события, диагностика, снимки и заметки. Повторное нажатие сгенерирует новый случайный набор.

Чтобы вернуться, выберите **Настройки → Реальные данные** или закройте окно предпросмотра. Сохранённая история настоящей сети остаётся в прежней базе; состояние паузы восстанавливается. Во время DEMO новые реальные сканирования приостановлены; уже запущенное сканирование может завершиться.
